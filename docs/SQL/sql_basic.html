代码规范

以下两种均可：

SELECT
    name,
    department
FROM
    employees;

SELECT name, department
FROM employees;

效率问题：如果 employees 表上没有合适的索引，数据库可能需要扫描整个表来找到所需的数据。对于这个简单的查询，如果 name 或 department 列经常被用于搜索或过滤，可以考虑在其上创建索引。

执行步骤：

虽然实际的执行过程比这复杂得多，但对于这条简单的查询，可大致理解为以下步骤：

  1. 语法解析： 数据库服务器首先会检查 SQL 语句是否符合语法规则。
  2. 权限检查： 数据库会验证是否有权限访问 employees 表并读取其中的数据。
  3. 选择列： 数据库会确定需要检索的列是 name 和 department。
  4. 读取数据： 数据库会从 employees 表的存储空间中读取这两列的数据。
  5. 返回结果： 数据库将读取到的数据以结果集的形式返回。

SQL 查询的基本执行顺序（简化版）：

  1. FROM 和 JOIN： 首先根据 FROM 和 JOIN 子句，将一个或多个表的数据组合起来，生成一个中间结果集。LEFT JOIN, RIGHT JOIN, FULL OUTER JOIN 都可能在这个阶段引入 NULL 值（在没有匹配的行的另一边的列中）。INNER JOIN 和 CROSS JOIN 不会主动引入 NULL 值，除非原始表就包含 NULL。
  2. WHERE： 对中间结果集中的每一行进行过滤，只保留满足 WHERE 条件的行。
  3. GROUP BY： 对经过 WHERE 过滤后的结果集进行分组。
  4. HAVING： 对分组后的结果进行过滤。
  5. SELECT： 对最终保留的行（如果是分组查询，则是每个分组）计算 SELECT 列表中指定的表达式，并选择列。
  6. DISTINCT： 如果有，对 SELECT 结果进行去重。
  7. ORDER BY： 对最终结果进行排序。
  8. LIMIT / TOP： 限制返回的行数。

案例分析

子查询问题

子查询： 嵌套在其他 SQL 查询内部的查询。子查询可以出现在 SELECT、FROM、WHERE、HAVING 等子句中。

效率问题： 在连接字段上创建索引可以显著提高 JOIN 操作的效率。数据库可以通过索引快速找到匹配的行，而不需要扫描整个表。

select a.name, b.bonus
from (
    select name, empId
    from Employee as a
    left join (
        select empId, bonus
        from Bonus as b
    )
)
where b.bonus < 1000;

  1. 缺少 JOIN 连接条件

  2. 子查询未命名导致无法在外层引用： 你在第一个子查询中使用了 as a 给 Employee 表起了别名，这是正确的。但是，你在第二个子查询 (select empId, bonus from Bonus as b) 内部也使用了 as b，这个别名只在第二个子查询内部有效。当你试图在外层的 WHERE 子句中使用 b.bonus 时，外层查询并不知道 b 指的是什么。

修正后的代码有如下两种写法，分别是 子查询 方式和 非子查询 方式：

-- 子查询方式
SELECT
    a.name,
    b_sub.bonus
FROM
    (SELECT name, empId FROM Employee) AS a
LEFT JOIN
    (SELECT empId, bonus FROM Bonus) AS b_sub ON a.empId = b_sub.empId
WHERE
    b_sub.bonus < 1000;

执行步骤：

  • 数据库服务器会先执行第一个子查询 (SELECT name, empId FROM Employee) AS a。这会从 Employee 表中选择 name 和 empId 这两列，并创建一个临时的结果集，别名为 a。
  • 然后，它会执行第二个子查询 (SELECT empId, bonus FROM Bonus) AS b_sub。这会从 Bonus 表中选择 empId 和 bonus 这两列，并创建一个临时的结果集，别名为 b_sub。
  • 接着，执行 LEFT JOIN 操作，根据 a.empId = b_sub.empId 这个条件，将第一个子查询的结果集 a 中的每一行与第二个子查询的结果集 b_sub 中 empId 相匹配的行进行连接。
    • 同样，如果 b_sub 中没有与 a 中 empId 匹配的记录，a 中的该行仍然会保留，而 b_sub 对应的列（在这里是 bonus）会显示为 NULL。
  • 最后，WHERE b_sub.bonus < 1000 这个条件会过滤连接后的结果集，只保留 b_sub.bonus 小于 1000 的行。
-- 非子查询方式
SELECT
    e.name,
    b.bonus
FROM
    Employee AS e
LEFT JOIN
    Bonus AS b ON e.empId = b.empId
WHERE
    b.bonus < 1000;

执行步骤：

  • 读取 Employee 表： 数据库首先会读取 Employee 表中的所有数据。
  • 读取 Bonus 表： 然后，数据库会读取 Bonus 表中的所有数据。
  • 执行连接操作： 对于 Employee 表中的每一行，数据库会尝试在 Bonus 表中找到 empId 相匹配的行。
  • 构建结果集（左连接）： 如果在 Bonus 表中找到了匹配的行，则将两表的数据合并到结果集中。如果没有找到匹配的行，Employee 表的记录仍然会保留在结果集中，但 Bonus 表对应的列会填充 NULL。
  • 应用 WHERE 子句： 数据库会根据 WHERE b.bonus < 1000 的条件过滤结果集，只保留 bonus 小于 1000 的行。
  • 选择列： 最后，数据库会从过滤后的结果集中选择 name 和 bonus 这两列的数据并返回。

效率比较：

在现代的 MySQL 数据库系统中，查询优化器通常非常智能。对于这两种查询，优化器很可能会意识到它们在逻辑上是等价的，并且可能会生成非常相似甚至完全相同的执行计划。

一般来说，对于这种简单的场景，第1种使用子查询的方式并不会带来任何性能上的优势，反而可能会因为引入了额外的子查询层次而增加一些微小的开销（例如创建和管理临时结果集）。 然而，这种开销通常非常小，可以忽略不计。

更高效的选择通常是第2种直接连接表的方式，因为它更简洁明了，也更容易被优化器理解和优化。

JOIN方式

  • LEFT JOIN（左连接）： 返回左表中的所有行，以及右表中与左表匹配的行。如果右表中没有匹配的行，则右表对应的列将返回 NULL。

    • 若右表有重复行，则左表在 ON 条件配对的那部分行也会被带着重复

  • INNER JOIN（内连接）： 只返回两个表中连接字段相匹配的行。

  • RIGHT JOIN（右连接）： 返回右表中的所有行，以及左表中与右表匹配的行。如果左表中没有匹配的行，则左表对应的列将返回 NULL。

    • 若左表有重复行，则右表在 ON 条件配对的那部分行也会被带着重复

  • FULL OUTER JOIN（全外连接）：

    • 如果两张表中某一行符合 ON 子句的连接条件，则将这两行组合起来

    • 如果左表中的一行在右表中没有匹配项，则左表中的该行会返回，右表的所有列将显示为 NULL

    • 如果右表中的一行在左表中没有匹配项，则右表中的该行会返回，左表的所有列将显示为 NULL。

    • 类似 Left join和 right join 的结合：

      SELECT * FROM TableA 
FULL OUTER JOIN TableB 
ON TableA.column = TableB.column
--- 等价于：
SELECT *
FROM TableA
LEFT JOIN TableB ON TableA.column = TableB.column
UNION
SELECT *
FROM TableA
RIGHT JOIN TableB ON TableA.column = TableB.column

  • CROSS JOIN（笛卡尔连接）：

    • 不需要 ON 子句
    • 结果集的行数等于 TableA 的行数乘以 TableB 的行数
    • 不关心两个表之间行的值是否匹配，只是简单地将所有行进行组合
    • 不引入 NULL： 除非原始表就包含 NULL，否则 CROSS JOIN 本身不会因为没有匹配而引入 NULL 值。

HAVING和WHERE

基础知识：

  • GROUP BY 子句： 将具有相同列值的行分组到一起。在 SELECT 列表中，只能包含分组列和聚合函数。
  • 聚合函数 (COUNT, SUM, AVG, MIN, MAX)： 对每个分组执行计算并返回单个值。
  • HAVING 子句： 用于过滤由 GROUP BY 子句产生的分组。HAVING 子句中的条件通常涉及聚合函数。

having和where的区别：

  • WHERE 子句的执行时机： WHERE 子句在数据分组之前执行，它用于筛选出符合条件的原始数据行。在执行 WHERE 子句时，COUNT(*) 这样的聚合函数还没有被计算出来，因此你不能在 WHERE 子句中直接使用它进行条件判断。

  • HAVING 子句的执行时机： HAVING 子句在 GROUP BY 子句之后执行，它用于筛选出符合条件的分组。在执行 HAVING 子句时，聚合函数的结果已经计算出来了，所以你可以使用 COUNT(*) 等聚合函数的结果进行条件判断。

因此，将过滤条件放在 WHERE 还是 HAVING 取决于想在分组前过滤单个行，还是在分组后过滤整个分组。

错误语句：

SELECT
    class
FROM
    Courses
GROUP BY class
WHERE COUNT(*) >= 5;

正确语句：

SELECT
    class
FROM
    Courses
GROUP BY
    class
HAVING
    COUNT(*) >= 5;

执行步骤（简化版，针对正确的代码）：

  • 读取 Courses 表。
  • 根据 class 列进行分组。
  • 对每个分组计算课程数量 (COUNT(*)）。
  • 使用 HAVING COUNT(*) >= 5 过滤分组，只保留课程数量大于等于 5 的分组。
  • 从保留的分组中选择 class 列的值并返回。

使用聚合函数又使用非聚合列

1251. 平均售价 - 力扣（LeetCode）open in new window

这个题要展示所有product的平均售价，可以使用left join的方式，将Products（as p）和UnitsSold（as u）表拼接，条件是：

  • p.product_id=u.product_id

  • u.purchase_date between p.start_date and p.end_date

但是在UnitsSold表中可能没有销售记录，left join 之后 units 等信息为NULL，所以 units 为NULL的行要将 average_price 设为0。这样容易出现如下代码的错误，即单个判断u.units是否为NULL，从语法上：

  • 使用 GROUP BY时，SELECT 列表中的表达式必须对于分组后的每一行都能确定一个唯一的值，意味着SELECT 列表中只能包含：

    1. GROUP BY 子句中列（在这里是 p.product_id）

    2. 聚合函数应用于其他列

    3. 由分组列和聚合函数组成的表达式

  • u.units 不是分组列，也没有被聚合函数包裹。在一个分组（比如 product_id = 1）中，可能有很多行记录，这些记录的 u.units 值可能不同（有些是实际销售数量，有些因为左连接没有匹配到销售记录而为 NULL）。数据库不知道在评估 when u.units is null 这个条件时，应该使用这个分组中的哪一行的 u.units 值来判断。这种情况下，大多数 SQL 数据库会报错，提示非聚合列的使用不合法。

  • 正确做法：判断整个分组的总销售数量 (SUM(u.units)) 是否为 NULL 或 0，而不是判断单个行的 u.units 是否为 NULL。

select
    p.product_id,
    case 
        when u.units is null then 0  -- 应该将u.units改为sum(u.units)
        else round(sum(p.price * u.units) / sum(u.units), 2) 
    end as average_price
from
    Prices as p
left join
    UnitsSold as u
on  
    p.product_id = u.product_id
    and
    u.purchase_date between p.start_date and p.end_date
group by
    p.product_id  -- 不能是u.product_id，因为p中才包含了全部的商品

上述代码使用了CASE WHEN 语句，其实还可以将其替换为：

COALESCE(
        ROUND(
            SUM(p.price * u.units) / NULLIF(SUM(u.units), 0),
            2
        ),
        0
    ) AS average_price

NULLIF 和 coalesce

  • NULLIF：NULLIF(expression1, expression2) 函数比较两个表达式的值。如果它们相等，则返回 NULL；如果它们不相等，则返回第一个表达式 (expression1) 的值。这里为了防止除法分母出现0

  • COALESCE：COALESCE(expression1, expression2, ..., expressionN) 函数按顺序评估参数列表中的表达式，并返回第一个非 NULL 的表达式的值。

对于如下代码：

COALESCE(
        ROUND(
            SUM(p.price * u.units) / NULLIF(SUM(u.units), 0),
            2
        ),
        0
    ) AS average_price

追踪对于一个没有销售记录的产品（即u.units为NULL）的计算过程：

  1. SUM(p.price * u.units): NULL。
  2. SUM(u.units): NULL。
  3. NULLIF(SUM(u.units), 0): NULLIF(NULL, 0) -> NULL。
  4. SUM(p.price * u.units) / NULLIF(SUM(u.units), 0): NULL / NULL -> NULL。
  5. ROUND(NULL, 2): NULL。
  6. COALESCE(NULL, 0): 0。

case when

SQL中的CASE WHEN语句：从基础到高级应用指南_case when sql-CSDN博客open in new window

CASE WHEN类似if-else逻辑，有两种基本形式：基于字段值 和 基于表达式：

-- 基于字段值的简单搜索
SELECT
  CASE status
    WHEN 'active' THEN '已激活'
    WHEN 'inactive' THEN '未激活'
    ELSE '未知状态'
  END AS status_label
FROM users;


-- 基于表达式的搜索
SELECT    
  CASE
    WHEN age > 18 THEN '成年人'
    WHEN age BETWEEN 6 AND 18 THEN '未成年人'
    ELSE '婴幼儿'
  END AS age_group
FROM people;

上面两个示例是新增一列数据，而这一列数据在原始的表里不存在（AS status_label和AS age_group不是CASE WHEN 一定要有的语法，而是重命名列明的语法）

和聚合函数一起使用

还可以和聚合函数一起使用，下例要这么理解，先根据products表里的categoryID列来分组，然后计算不同组内的unitPrice列的均值：

SELECT
    categoryID,
    AVG(unitPrice) AS avgPrice,
    CASE 
        WHEN AVG(unitPrice) > 50 THEN
            'high'
        ELSE
            'low'
    END AS priceCategory
FROM
    products
GROUP BY categoryID;

子查询

用于子查询：

SELECT
    productName,
    unitPrice,
    (CASE 
        WHEN unitPrice > (SELECT AVG(unitPrice) from products) THEN
            'aboveAvg'
        ELSE
            'belowAvg'
    END) AS PriceComparison
FROM
    products

解释：

  • 子查询计算平均值： 在 CASE 语句中，(SELECT AVG(unitPrice) from products) 这是一个子查询。这个子查询会独立地执行一次，计算出 products 表中所有产品的平均 unitPrice。
  • 行级比较： 外层查询会遍历 products 表的每一行。对于每一行，它会获取当前行的 unitPrice，然后将其与子查询返回的那个固定的平均值进行比较。
  • 不需要 GROUP BY： 因为平均值是针对整个表计算出来的，并且我们是在每一行上进行独立的比较，所以不需要使用 GROUP BY 子句。我们不是在寻找每个分组的平均值，而是将每个产品的价格与一个全局的平均价格进行比较。

上述代码的错误写法：

SELECT
    productName,
    unitPrice,
    (CASE 
        WHEN unitPrice > AVG(unitPrice) THEN
            'aboveAvg'
        ELSE
            'belowAvg'
    END) AS PriceComparison
FROM
    products

解释：

  • 聚合函数的上下文： 在 SELECT 列表中直接使用聚合函数时，如果没有 GROUP BY 子句，大多数 SQL 数据库会认为你想要计算整个表的聚合值。然而，又在同一 SELECT 列表中同时选择了非聚合列 (productName, unitPrice)。
  • 逻辑冲突： 数据库会困惑你想要比较什么。你是想将每一行的 unitPrice 与整个表的平均 unitPrice 进行比较，还是想做其他的事情？在没有明确的 GROUP BY 指示的情况下，数据库通常会报错，因为它不知道 AVG(unitPrice) 应该对应于哪一个分组（或者说，它应该如何将单个行的值与整个表的聚合值进行比较）。

即在没有 GROUP BY 的情况下，直接在 SELECT 列表中使用 聚合函数 并同时选择 非聚合列 会引起歧义，导致数据库报错。

加入窗口函数

SELECT
    productName,
    unitPrice,
    stockQuantity,
    CASE 
        WHEN stockQuantity > AVG(stockQuantity) over() THEN
            'above avg'
        ELSE
            'below avg'
    END AS avg_stockQuantity
FROM 
    products
roducts;

关键在于 AVG(StockQuantity) OVER () 这部分。

窗口函数的工作方式：

  • 计算范围： 窗口函数对一组称为“窗口”的行执行计算，这个窗口与当前正在处理的行相关。
  • 每行返回一个值： 与普通的聚合函数（在没有 GROUP BY 的情况下）为整个结果集返回一个单一的值不同，窗口函数会为结果集中的每一行都返回一个值。

AVG(StockQuantity) OVER () 的含义：

  • AVG(StockQuantity)：这是一个计算平均值的聚合函数。
  • OVER ()：这是窗口函数的关键部分。OVER() 子句定义了窗口的范围。在这里，空的 OVER() 表示窗口是整个结果集，也就是说，它会计算 Products 表中所有行的 StockQuantity 的平均值。

因此，这段代码的执行逻辑是：

  1. 对于 Products 表中的每一行，都会计算出整个表中 StockQuantity 的平均值。
  2. 然后，将当前行的 StockQuantity 与这个计算出来的平均值进行比较。
  3. 根据比较的结果，CASE 语句会判断该产品的库存是高于平均水平还是低于平均水平。
  4. 最终，查询会返回每个产品的名称、单价、库存数量以及一个表示其库存水平与平均水平比较的列 StockComparison。

更复杂点的：在窗口函数内，对categoryID分组，并在组内根据unitPrice排序，再计算各组的均值。实现如下：

SELECT
    productName,
    unitPrice,
    stockQuantity,
    CASE 
        WHEN stockQuantity > AVG(stockQuantity) over(partition by categoryID order by unitPrice) THEN
            'above avg'
        ELSE
            'below avg'
    END AS avg_stockQuantity
FROM 
    products

将case when用在order by中，实现动态排序：

SELECT

    unitPrice
FROM products
ORDER BY
    CASE
        WHEN categoryID = 2 THEN unitPrice
        WHEN categoryID = 1 THEN unitPrice * 0.2
        ELSE unitPrice * 1.1
    END;

上述代码其实和下面的三元表达式类似：

update salary set sex=IF(sex='f','m','f')

外键

定义：

外键是一个表（Child表）中的一列或一组列，它们引用（指向）另一个表（Parent表）中的主键（或唯一键）。

  • 引用表 (Referencing Table) 或 子表 (Child Table)：包含外键的那个表。
  • 被引用表 (Referenced Table) 或 父表 (Parent Table)：外键引用的那个表，这个表通常包含被引用列的主键或唯一键。

作用：

外键的主要作用是 在两个表之间建立和强制执行联系（关系）

意味着：

  • 你不能在子表中创建一个记录，使其外键列的值在父表被引用列中不存在。例如，你不能创建一个订单记录，而该订单所属的客户在客户表中根本不存在。
  • 你不能删除父表中的一个记录，如果子表中有记录引用了它（除非你设置了特殊的删除规则）。例如，你不能轻易删除一个客户，如果该客户已经有了订单。
  • 任意一个 子表 中的 外键 (如果不是 NULL) 一定在 父表 表中都能找到对应的列。

创建模板：

CREATE TABLE ParentTable (
    parent_id INT PRIMARY KEY,
    parent_name VARCHAR(255)
);

CREATE TABLE ChildTable (
    child_id INT PRIMARY KEY,
    child_name VARCHAR(255),
    parent_id INT,
    -- 定义外键
    FOREIGN KEY (parent_id) REFERENCES ParentTable(parent_id)
    -- 可选：定义参照动作
    -- ON DELETE CASCADE
    -- ON UPDATE CASCADE
);
  • FOREIGN KEY (parent_id): 指定 ChildTable 表中的 parent_id 列作为外键。
  • REFERENCES ParentTable(parent_id): 指定这个外键引用 ParentTable 表中的 parent_id 列。ParentTable 的 parent_id 列必须是主键或唯一键。

例子：

假设有两个表：Customers (客户表) 和 Orders (订单表)。

  • Customers 表有一个主键 customer_id。
  • Orders 表有一个 order_id 作为主键，还有一个 customer_id 列。

我们可以在 Orders 表的 customer_id 列上创建一个外键，引用 Customers 表的 customer_id 主键。

CREATE TABLE Customers (
    customer_id INT PRIMARY KEY,
    customer_name VARCHAR(255)
);

CREATE TABLE Orders (
    order_id INT PRIMARY KEY,
    order_date DATE,
    customer_id INT,
    FOREIGN KEY (customer_id) REFERENCES Customers(customer_id) ON DELETE RESTRICT
);
  • Orders 是子表，Customers 是父表。
  • Orders.customer_id 是外键，引用 Customers.customer_id。
  • ON DELETE RESTRICT 意味着如果你尝试删除 Customers 表中一个已经有订单的客户，操作会被阻止。
  • 任意一个 Orders 中的 customer_id (如果不是 NULL) 一定在 Customers 表中都能找到对应的列。
  • 在 Orders 表中插入或更新一条记录，其 customer_id 在 Customers 表中找不到，数据库就会报错，拒绝该操作。
  • 注意： 如果 Orders.customer_id 列允许为 NULL (也就是在创建表时没有定义为 NOT NULL)，那么 NULL 值是允许的，并且 NULL 外键不要求在父表中找到匹配项。一个 NULL 外键通常表示该记录与父表没有关联。但在你这个例子中，customer_id 是一个关联的关键，通常会设置为 NOT NULL。

总结：

外键约束是单向的，从子表指向父表。它确保子表中引用的有效性，但不强制要求父表中的记录一定被子表引用。这正是关系型数据库中一对多（一个客户可以有多个订单）关系的标准建模方式。

OR NULL

布尔表达式与 NULL 进行 OR 运算的规则：

  • TRUE OR NULL -> TRUE
  • FALSE OR NULL -> NULL

用一个例题来熟悉：1084. 销售分析 III - 力扣（LeetCode）open in new window

要求列出仅在规定时间范围内出售的商品（有的商品同时在别的时间也出售了），若使用布尔表达式与NULL进行 OR 的思路，则代码如下。count()函数不会统计NULL行，所以 代码中的布尔表达式 OR NULL有三种情况：

  1. True OR NULL = True

  2. False OR NULL = NULL（在规定时间范围外也有销售，不统计）

  3. NULL OR NULL = NULL （sale_date为空）

select
    p.product_id,
    p.product_name
from 
    Sales as s
left join
    Product as p
on
    s.product_id = p.product_id
group by s.product_id
having 
    count(*) = count(s.sale_date between '2019-01-01' and '2019-03-31' or null)

其实上述代码等同于：

SELECT
    p.product_id,
    p.product_name
FROM
    Sales AS s
LEFT JOIN
    Product AS p ON s.product_id = p.product_id
GROUP BY
    s.product_id
HAVING
    COUNT(*) = SUM(CASE WHEN s.sale_date BETWEEN '2019-01-01' AND '2019-03-31' THEN 1 ELSE 0 END)

但是上述代码执行超时，可以使用如下的思路改进，如果去掉EXISTS语句，还是比较好理解的，但是Product表中 可能存在无交易记录的商品，这些商品自然也不会在NOT IN条件内，也不希望它们在结果中呈现出来。而EXISTS后面的条件是为了解决这个问题的。

SELECT
    p.product_id,
    p.product_name
FROM
    Product AS p
WHERE
    p.product_id NOT IN ( -- 排除掉那些有不合格销售记录的产品
        SELECT DISTINCT s.product_id
        FROM Sales AS s
        WHERE
            s.sale_date < '2019-01-01'
            OR s.sale_date > '2019-03-31'
            OR s.sale_date IS NULL
    )
    AND EXISTS ( -- 并且确保这个产品在 Sales 表中至少有一条销售记录
        SELECT 1
        FROM Sales AS s2
        WHERE s2.product_id = p.product_id
    );

EXISTS 和 select 1

select 1中的1是无意义的，填任何数字都可以

对于代码：

    AND EXISTS ( -- 并且确保这个产品在 Sales 表中至少有一条销售记录
        SELECT 1
        FROM Sales AS s2
        WHERE s2.product_id = p.product_id

  • select 1的作用：符合where条件的行有几个，则返回结果有几个1

  • EXISTS：若后面的结果集中，存在数据，则为True，否则为False。EXISTS不在乎数据有多少、是什么，只在乎有没有

group_concat()

GROUP_CONCAT()语法：

GROUP_CONCAT(
    DISTINCT expression1
    ORDER BY expression2
    SEPARATOR sep
)

  • DISTINCT 确保了 expression1 列中的每个名称在连接的字符串中只包含一次。

  • order by 对唯一的名称进行升序排序，这是默认的顺序，因此可以省略

  • 关键字 SEPARATOR 指定产品名称应以 sep 分隔

如在1484. 按日期分组销售产品 - 力扣（LeetCode）open in new window中，要求结果列表中有一列内容类似Basketball,Headphone,T-shirt，string类型，则可以使用group_concat函数实现：

select 
    sell_date,
    count(distinct product) as num_sold,
    group_concat(
        distinct product 
        order by product
        separator ','
    ) as products
from
    Activities
group by 
    sell_date
order by 
    sell_date ASC
