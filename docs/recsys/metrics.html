召回阶段

recall

所有正样本有多少个被预测对，即体现找全率。

recall=TPTP+FN

分母表示所有的正样本：预测对了，预测为了正样本 + 预测错了，预测为了负样本。

precision

准确度。所有对正样本预测的结果中，有多少是预测对的

precition=TPTP+FP

分母表示所有预测为正 的结果。

NDCG

CG和DCG只是单纯的进行求和，无法进行不用用户之间的对比，因此需要对其进行标准化，从而诞生了NDCG。标准化后得到的NDCG是一个相对值，从而使得即使不同的用户之间可以进行比较。

用于评估推荐系统排序质量的一种指标。它结合了推荐列表中项目的相关性和位置信息，用于衡量推荐系统在给定查询或用户的情况下生成的推荐列表的质量。

GAUC

图解AUC和GAUC - 知乎 (zhihu.com)open in new window

auc反映的是整体样本间的一个排序能力，

而在计算广告领域，我们实际要衡量的是不同用户对不同广告之间的排序能力，

因此实际应该更关注的是同一个用户对不同广告间的排序能力。

实际处理时权重一般可以设为每个用户view或click的次数，而且会过滤掉单个用户全是正样本或负样本的情况。

问题：

  • 为什么使用用户的view或click次数作为权重？

    1. 样本不平衡问题：在实际的推荐系统中，正样本（用户点击的项）和负样本（用户未点击的项）通常是不平衡的，即负样本的数量远远超过正样本的数量。使用用户的view或click次数作为权重可以帮助缓解这种不平衡问题，使得模型更加关注那些被用户重复点击或观看的项目，提高对正样本的重视程度。
    2. 个性化考量：不同用户对于推荐系统的行为可能会有所不同，一些用户可能会更加频繁地与系统进行交互，而另一些用户可能会相对较少。因此，将用户的view或click次数作为权重可以更好地个性化地反映用户的行为特征，提高推荐系统的个性化程度。

  • 为什么要过滤掉用户全是正样本或负样本的情况？

    过滤单一用户情况：在一些情况下，某些用户可能会全部点击或者全部不点击推荐的项目，这种情况可能会影响模型的泛化能力。
